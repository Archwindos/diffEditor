# DiffEditor 使用说明

## 让 agent 把修改交给你审阅

```text
agent 读取基线 → 提交候选稿 → 你审阅、编辑 → 确认保存与备份 → 回执返回，agent 继续
```

将便携包中的 `skill/diffeditor` **完整文件夹**复制到个人 Codex skills 目录；项目源码中的对应目录是 [`skills/diffeditor`](../skills/diffeditor)。引用文档和 Python 助手需要一起保留。当前随包 skill 面向 Codex，不安装 hooks，也不修改 agent 配置。

安装后，可以直接对 Codex 说：

> 使用 $diffeditor 修改这篇论文。先把修改送到 DiffEditor，我自己审阅、编辑并确认保存；请等待保存回执后再继续，不要直接写原文件。

agent 会读取不可变基线，将完整候选稿放进软件草稿区，再提交审阅。界面将候选稿标为“AI 提供的草稿，确认后保存至：目标路径”。提交后，agent 提示你在软件内审阅，并在当前任务中等待；你无需再回聊天说“我确认了”。

保存回执记录实际保存的一侧、文件哈希及时间等信息。你可能保留了原稿，也可能手动改过候选稿，因此收到回执不等于 AI 提案被全部接受。多文件提案逐文件记录结果，一个文件已保存不代表全部完成。

默认最多等待 **30 分钟**。超时、退回、关闭或删除尚未保存的比较，以及冲突或保存失败，都会按实际状态返回，不视为批准。窗口缩到托盘不影响等待；彻底退出软件会断开连接。若 agent 任务已经停止或等待已超时，之后保存不会自动唤醒已结束的聊天。

## 在软件中审阅与保存

解压便携包，完整保留程序旁的资源文件，双击 `DiffEditor.exe`。

1. **开始比较。** 点击 **新建文本比较**，直接在两侧输入或粘贴，无需文件。**打开文件** 会让左右两侧从同一文件开始，可一次选择多份、分别审阅；**双文件比较** 用于两个独立文件。也可拖入文件。
2. **查看与修改。** 两侧以 **原稿（左）／新稿（右）** 区分，均可直接编辑。悬停到差异块附近，原稿一侧的绿色左箭头将新稿替换到原稿，新稿一侧的红色右箭头将原稿替换到新稿。长段落默认自动换行；可选择文本，使用查找、撤销、重做、差异跳转及折叠相同行。最右侧的红绿全文概览支持点击、拖动和滚轮定位；原稿编辑区的普通滚动条停止滚动后隐藏。
3. **保留草稿。** 编辑会缓存为草稿，**不会自动写入原文件**。可以切换文件或正常关闭；异常退出后可恢复最近已经缓存的版本。
4. **确认保存。** 点击 **保存原稿** 或 **保存新稿**，核对完整目标路径、编码、备份位置和冻结待保存内容，再点击 **确认并保存**。`Ctrl+S` 只打开确认窗口。无文件文本使用 **另存为…**，两侧各自选择新文件位置，再进入确认；选择已有文件时拒绝覆盖，需改用新文件名。
5. **继续下一轮。** 保存成功后，全宽单栏显示保留的一侧，可查找、复制和自动换行；重新打开仍显示该版本。同一原稿的两侧旧草稿不能继续覆盖该原稿。点击 **继续编辑**，从刚保存的磁盘版本开始新一轮。双文件比较分别记录两侧状态，另一文件未完成时可点击 **继续审阅另一文件**。

![最终保存确认：核对目标路径、编码、备份位置和冻结待保存内容](images/save-confirmation.png)

*同一独立演示文档在 v0.1.6 中的最终保存确认。截图停在“确认并保存”之前，展示的是待保存内容，不是已经保存的证据。*

比较列表中的 **关闭** 会将比较收入 **已关闭**，可随时重新打开，双侧草稿保留。**删除** 经确认后移除比较及缓存文本，不能恢复；正式文件、已保存内容和备份不受影响。

左下角 **设置 → 关闭窗口后转到后台** 默认开启。点击窗口叉号会先缓存草稿，再隐藏到系统托盘（可能在隐藏图标区）；点击托盘图标或桌面快捷方式可重新打开，托盘右键菜单的 **退出** 才会彻底退出。取消此设置后，叉号会在缓存草稿后退出。设置会保留。

## 文件、草稿与恢复

- **编码与换行。** 默认识别 UTF-8/BOM、带 BOM 的 UTF-16；旧中文文本可选择 GB18030 后打开，保存编码也可明确选择。原有混合换行和末尾换行尽量按原始行映射保留；未修改文件逐字节保留。
- **草稿位置。** 默认位于 `%LOCALAPPDATA%\DiffEditor\drafts`；agent 候选输入位于同级 `inbox`，均不是正式稿。关闭应用不删除草稿或备份。删除比较会清除其缓存文本，但保留提交标识、删除状态和保存回执等最小记录，防止重复提交复活已删除比较。
- **保存前备份。** 每次确认保存已有文件，先将旧稿备份到原文件同目录的 `.diffeditor-backups`。备份名称唯一，不覆盖、不自动清理；保存后可点击 **查看备份**。新文件没有旧稿备份。
- **外部修改冲突。** 保存前检查原稿内容及文件身份；原稿被外部修改、替换或删除时停止写入并保留草稿。**基于磁盘继续** 会保留旧审阅记录，并从当前磁盘建立新一轮，需要的旧草稿内容可再复制过去。
- **保存失败或中断。** 界面显示原因；中断后仅在目标与备份均验证通过时恢复“已保存”，不自动重写或回滚文件。

原稿哈希检查与文件替换之间仍有很短的竞争窗口，请避免确认保存时由其他程序同时写同一文件。软件与 skill 提供人工审批工作流，不改变 agent 的操作系统权限，不能拦截绕过软件的直接写盘。

## 用本地 CLI 对接 agent

CLI 通过本机命名管道提供四个命令，候选稿以结构化 JSON 提交，结果也返回 JSON。便携包借用自带 Electron 运行，不要求另装 Node。

```text
diffeditor.cmd baseline "D:\论文\main.tex"
diffeditor.cmd submit --file "候选 JSON 的绝对路径"
diffeditor.cmd wait "reviewId" --timeout 1800
diffeditor.cmd status "reviewId"
```

`baseline` 取得不可变原稿；`submit` 提交包含基线 ID 和完整候选文本的 UTF-8 JSON；`wait` 等待一个或多个 reviewId 的人工结果；`status` 查询逐文件状态。只有目标同时具有 `status: saved` 和保存 `receipt` 才能报告已保存。提交成功或命令退出码为 0 本身不证明保存。

其他 agent 可以按此本地协议接入，但需要自行实现候选稿提交、等待及结果处理，并遵守人工审批约束；当前不承诺所有平台开箱即用。CLI 没有批准、保存或强制覆盖命令，聊天中的“同意”也不能代替软件内的最终确认。

完整提交结构、参数数组调用、重试、冲突及逐文件回执见 [CLI 文档](cli.md)；随包 skill 的 `references/cli.md` 提供相同协议说明。配套 Python 助手避免将正文拼入命令行，可用 `DIFFEDITOR_HOME` 指向包含 `diffeditor.cmd` 的目录，也可自动发现本机项目路径。不要使用真实论文作为测试样本。

## 从源码运行与打包

需要 **Node.js 22.12+ 或 24** 和 npm。Windows 的 AI 助手集成测试还需要 PATH 中的 Python 3，也可用 `DIFFEDITOR_TEST_PYTHON` 指定 Python 可执行文件。

```text
npm ci
npm run typecheck
npm test
npm run build
npm start
npm run package
```

当前便携目录为 `release/0.1.7/win-unpacked`，需完整复制或打包。升级前从托盘菜单退出旧版（无托盘的旧版正常关闭），再启动新版；原有缓存草稿继续保留。首次安装和打包需要下载公开依赖，软件运行不需要网络。应用仅在本机命名管道处理 `baseline`、`submit`、`status`、`wait`，桌面渲染器阻止远程网络请求。

测试覆盖文件保真、草稿修订、原稿冲突、备份、保存中断及命令行边界。开发时可用 `DIFFEDITOR_DATA_DIR`、`DIFFEDITOR_PIPE` 隔离测试草稿和接口；普通用户无需设置。
